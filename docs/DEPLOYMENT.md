# Deployment Guide — ₹0 stack

> **Fastest path (used for this project): everything on Render + Neon.** `render.yaml` defines two free services: `smart-farm-api` (Node) and `smart-farm-web` (static React site). They are wired to each other automatically (API URL ↔ CORS origin), and the API build creates and seeds the database. Steps: create a Neon project → Render **New → Blueprint** → pick the repo → paste the Neon connection string → **Apply**. The Cloudflare Pages route below is the alternative for unlimited CDN bandwidth.

**Cloudflare Pages** (frontend) → **Render Free** (API) → **Neon Free** (PostgreSQL). Total time is about 30 minutes. You need GitHub, Neon, Render and Cloudflare accounts, all free. Only Render may ask for a card, and the free plan is not charged.

```
GitHub repo ──push──▶ Render (builds backend/)  ──SQL/TLS──▶ Neon Postgres
            └─push──▶ Cloudflare Pages (builds frontend/) ──HTTPS /api──▶ Render
```

## 1. Prepare the repository (GitHub)

```bash
cd smart-farm-advisory
git init -b main
git add .
git commit -m "Smart Farm Advisory — initial commit"
# create an EMPTY repo on github.com (no README), then:
git remote add origin https://github.com/<you>/smart-farm-advisory.git
git push -u origin main
```

> `.gitignore` already excludes `.env` files and `*.xlsx`. **Never commit the original spreadsheet**: it contains plaintext passwords. The repo only carries `backend/seed-data/*.json`, where passwords are already bcrypt-hashed.

## 2. Database — Neon

1. https://console.neon.tech → **New project** → name `smart-farm`, Postgres **16**, region **AWS Asia Pacific (Singapore)** (closest to India).
2. **Dashboard → Connect** → toggle **Connection pooling ON** → copy the string. It looks like:
   `postgres://neondb_owner:xxxx@ep-cool-name-123456-pooler.ap-southeast-1.aws.neon.tech/neondb?sslmode=require`
3. Create the schema and seed data. **Easiest:** do nothing — the Render build command (`render.yaml`) runs `db:migrate && db:seed`, which create the schema and load the data on the first deploy and are no-ops afterwards. **Or** run it from your computer:
   ```bash
   cd backend
   npm ci
   DATABASE_URL='<neon string>' DATABASE_SSL=true npm run db:reset
   # ✓ 51 farmers ✓ 133 fields ✓ 3,024 crop records ✓ 399 sensors ✓ ~67k readings …
   ```
   On Windows PowerShell: `$env:DATABASE_URL='<neon string>'; $env:DATABASE_SSL='true'; npm run db:reset`
4. Check: Neon **Tables** shows 10 tables, and `SELECT count(*) FROM sensor_readings;` returns about 67,000. Storage used is about 25 MB of the 512 MB free.

**Alternative — Supabase:** create a project → **Connect → Session pooler** string → same `npm run db:reset`. Nothing else changes.

## 3. Backend — Render

**Option A, Blueprint (one click):** Render dashboard → **New → Blueprint** → select the repo. Render reads `render.yaml`, then asks you for:
- `DATABASE_URL` = the Neon pooled string
- `CORS_ORIGINS` = leave as `http://localhost:5173` for now; you'll update it in step 7
- `APP_URL` = same

`JWT_SECRET` and `INGEST_API_KEY` are generated automatically.

**Option B, manual:** **New → Web Service** → repo → Root directory `backend` · Runtime Node · Build `npm ci` · Start `npm start` · Instance **Free** · Health check path `/api/health` · then add the environment variables from `backend/.env.example` (`NODE_ENV=production`, `DATABASE_SSL=true`, …).

When the deploy goes green, open `https://smart-farm-api.onrender.com/api/health` → `{"status":"ok","db":"ok",…}`.

## 4. Environment variables summary

| Where | Variable | Value |
|---|---|---|
| Render | `NODE_ENV` | `production` |
| Render | `DATABASE_URL` | Neon pooled connection string |
| Render | `DATABASE_SSL` | `true` |
| Render | `JWT_SECRET` | 64+ random chars (auto-generated by Blueprint) |
| Render | `INGEST_API_KEY` | random. Give it to your IoT gateway |
| Render | `CORS_ORIGINS` | `https://smart-farm.pages.dev,*.smart-farm.pages.dev` (the second entry allows preview deploys) |
| Render | `APP_URL` | `https://smart-farm.pages.dev` |
| Render (optional) | `SMTP_HOST/PORT/USER/PASS/FROM` | e.g. Brevo free SMTP (300 mails/day) for verification / reset / report e-mails |
| Cloudflare Pages | `VITE_API_URL` | `https://smart-farm-api.onrender.com` (no trailing slash) |
| Cloudflare Pages | `NODE_VERSION` | `22` |

Generate secrets locally: `node -e "console.log(require('crypto').randomBytes(48).toString('hex'))"`

## 5. Frontend — Cloudflare Pages

1. https://dash.cloudflare.com → **Workers & Pages → Create → Pages → Connect to Git** → pick the repo.
2. Build settings:
   - Framework preset: **Vite** (or None)
   - Build command: `npm ci && npm run build`
   - Build output directory: `dist`
   - Root directory: `frontend`
   - Environment variables: `VITE_API_URL`, `NODE_VERSION=22`
3. **Save and Deploy** → you get `https://smart-farm.pages.dev`. `public/_redirects` makes deep links like `/app/sensors` work on refresh.

*Vercel alternative:* Import project → Root `frontend` → framework Vite → env `VITE_API_URL` → Deploy (`vercel.json` handles SPA routing). *Netlify:* base `frontend`, build `npm run build`, publish `frontend/dist`.

## 6. Test everything

```bash
API=https://smart-farm-api.onrender.com
curl $API/api/health
# full automated suite against the live DB (creates & deletes a temp farmer):
cd backend && DATABASE_URL='<neon>' DATABASE_SSL=true INGEST_API_KEY='<render value>' npm test
```
In the browser: open the Pages URL → log in with `demo@smartfarm.in / Demo@1234` → check the dashboard, sensors, recommendations (apply one), analytics and settings. Then register a new account and confirm you get the next Farmer ID (`FRM-0052`).

**Live data demo:** stream simulated sensor readings into production:
```bash
cd backend
DATABASE_URL='<neon>' DATABASE_SSL=true API_URL=$API INGEST_API_KEY='<render value>' \
  npm run simulate -- --farmer FRM-0051 --interval 10
```
Keep the dashboard open: the green **Live** dot pulses and values update without a refresh.

For Postman/Insomnia, see the curl examples at the end of `docs/API.md`. Log in, copy the token, and set it as a Bearer token on the collection.

## 7. Lock down CORS

Back on Render, set `CORS_ORIGINS=https://smart-farm.pages.dev,*.smart-farm.pages.dev` (plus your custom domain if you add one) and `APP_URL`. Render redeploys automatically.

## 8. Custom domain (optional)

- **Frontend:** Pages project → **Custom domains → Set up** → `farm.yourdomain.in`. If the domain's DNS is on Cloudflare it's automatic; otherwise add the CNAME it shows.
- **API:** Render service → **Settings → Custom Domains** → `api.yourdomain.in` → add the CNAME → TLS is issued automatically.
- Update `VITE_API_URL` (and redeploy Pages), `CORS_ORIGINS` and `APP_URL`.
- Cheap `.in` domains cost about ₹500–800/yr. A free alternative is a `*.pages.dev` subdomain.

## 9. CI/CD

Already wired:
- **Render** auto-deploys `backend/` on every push to `main` (`autoDeploy: true`).
- **Cloudflare Pages** builds every push. `main` goes to production, and other branches and PRs get preview URLs.
- **GitHub Actions `ci.yml`** spins up Postgres 16, runs `db:reset` and the 19 API tests, and builds the frontend on every push and PR. Turn on *Settings → Branches → require status checks* to block broken merges.
- **`keep-warm.yml`** (optional): set repository variable `API_URL` to ping `/api/health` every 10 min during daytime IST.

## 10. Operating on free tiers

| Concern | What to do |
|---|---|
| First request after idle takes ~1 min | Expected on Render Free. The UI shows "server may be waking up". Use keep-warm, or upgrade to Starter ($7/mo) |
| Neon storage (0.5 GB) | ~67 k readings ≈ 25 MB. At 3 sensors × 133 fields × every 15 min you add about 38 k rows/day (~10 MB/day). Add a retention job, e.g. `DELETE FROM sensor_readings WHERE "timestamp" < now() - interval '90 days'`, or roll old data into daily aggregates |
| Render bandwidth (5 GB/mo) | Responses are gzip-compressed and charts use bucketed analytics endpoints, not raw rows |
| Backups | Neon Free keeps 6 h of history (point-in-time restore). For more, run `pg_dump "$DATABASE_URL" > backup.sql` weekly |
| Reset demo data | `npm run db:reset` (⚠ deletes everything) |

## Troubleshooting

| Symptom | Fix |
|---|---|
| `Origin … is not allowed` (403) | Add the exact frontend origin to `CORS_ORIGINS` (no trailing slash) |
| `self-signed certificate` / SSL errors | `DATABASE_SSL=true`; use the Neon **pooled** host |
| Login works but pages 404 on refresh | `_redirects` (Pages / Netlify) or `vercel.json` must be in the deployed output — they are by default |
| `Schema already present` | Expected on the second run of `db:migrate`. Use `db:reset` to rebuild |
| Live dot stays grey | Some proxies buffer SSE. The app falls back to 60 s polling automatically |
| Weather card says unavailable | Open-Meteo blocked or down. Everything else keeps working |
